#exceljs compatibility (@xlvane/compat)

@xlvane/compat offers the commonly used part of the exceljs 4.4.0 API on top of xlvane, so that code written for exceljs keeps working after one change in package.json:

"dependencies": {
  "exceljs": "npm:@xlvane/compat@^1"
}

npm installs an alias <alias>@npm:<name> under the alias name in node_modules (npm/cli docs/lib/content/using-npm/package-spec.md, "Aliases"), so require('exceljs') and import ExcelJS from 'exceljs' load @xlvane/compat.

  • ESM: import ExcelJS from 'exceljs' works as with exceljs. @xlvane/compat is an ES module, so named imports (import { Workbook } from 'exceljs') work too; exceljs 4.4.0 rejects them because it is a CommonJS package.
  • CommonJS: const ExcelJS = require('exceljs') needs Node.js 22.12 or later. The package is ESM-only and exports the ExcelJS object under the name "module.exports", which require() of an ES module returns directly from Node.js 22.12 on (Node.js doc/api/modules.md, "Loading ECMAScript modules using require()"). engines.node is >=22.12.
  • Unsupported API throws an XlvError with code XLV_E_NOT_SUPPORTED, naming the method (docs/errors.md). Nothing is dropped silently.

Status: supported means the same behaviour as exceljs for the cases covered by the ported tests (tests/exceljs/). Partly means supported with the difference given in the notes. Not supported means it throws XLV_E_NOT_SUPPORTED. The source column points to the exceljs 4.4.0 implementation (paths relative to the package root, as installed in bench/node_modules/exceljs).

#Writing workbooks that were read from files

A workbook loaded with xlsx.load() is written again by xlsx.writeBuffer() (tests/exceljs/corpus-roundtrip.test.ts loads and saves every file of the POI corpus the layer reads). Where a file holds something xlvane does not write as it is, the layer writes the closest valid form (D-R01):

  • Page setup paperSize, copies, horizontalDpi or verticalDpi of 0 (allowed by the schema, refused by Office, [MS-OI29500] §2.1.638) are left out, so the defaults apply. exceljs writes the 0.
  • Shared-formula groups the writer cannot write as shared (master not the top-left cell of its range, groups that overlap each other or an array formula) are written as one ordinary formula per cell, translated from the master as cell.formula gives it; a cell whose formula cannot be translated keeps its cached result as a value.
  • EMF and WMF pictures are written unchanged (image/x-emf, image/x-wmf, as Excel declares them); workbook.addImage accepts them as well.
  • A hyperlink with neither a target nor a location is not read (exceljs, which reads only links with a relationship, drops it too); a target that is itself a place in the workbook (#Sheet2!A1) is not joined with the location.
  • Row heights above 409.5 points are read as 409.5; 409.5 itself, which Excel writes, is accepted.
  • A table whose style is a custom style of the file is written without a style name, because xlvane does not write the file's custom table styles; a style name set in code must still be one of the built-in names.
  • Totals-row formulas keep their cached results.
  • activeTab and firstSheet count chart sheets in the file; chart sheets are not loaded, so the indexes are mapped to the worksheet they fall on, or the worksheet before a chart sheet.
  • Row height, visibility and outline level are also read for rows without cells, up to the sheet's dimension or its last cell; rows after both are not looked at.

#Other differences found in the pre-release review

  • worksheet.dimensions is a Range as in exceljs (top, left, bottom, right, tl, br, range, $range, shortRange, count, model, toString(); an empty sheet gives the model { top: 0, left: 0, bottom: 0, right: 0 } and "A1:A1"). intersects, contains and forEachAddress are not implemented.
  • A 7-digit tab colour such as 'FFC0000' (exceljs README) is completed with a final 0 (FFC00000); exceljs writes the 7 digits.
  • A solid conditional-format fill reads back with bgColor (the core writes the same foreground and background colour), also when it was set with fgColor.
  • row.destroy() and cell.destroy() do nothing; the row or cell stays usable (exceljs deletes its internals).
  • Errors found while writing name the worksheet and, for cell values and styles, the cell (error.location).
  • worksheet.tables and dataValidations.model have no prototype: keys such as constructor or __proto__ are plain entries.
  • CSV writing: a field whose first character after any NUL characters is a formula character is escaped (NULs are removed when writing); with formatterOptions.quote: false, a field with CR, LF or the delimiter throws XLV_E_INVALID_OPTION (fast-csv writes it and the CSV then has other fields or rows). CSV reading: fields such as constructor or __proto__ stay text.
